## Hypotheses (untested, not findings)

1. **A possible crash on `null` or non-string email.**
   - With `{"email": None}` or `{"email": 1}`, `.strip()` raises `AttributeError` instead of returning a validation error.
   - If the code before the change was `request.get("email", "")` without `.strip()`, then `None` used to give "email is required". In that case the edit turned a validation error into a crash, which is a regression.
   - The pre-change code is not in `inputs/`, so whether this is a regression is unknown.
   - The settling check is one probe in a copy: `validate({"email": None})`.
   - Grade if confirmed: user-visible. It would then route as a local fix, not a skill change, because no warning sign was visible at the time.
2. **Coverage of the empty string may have been lost.**
   - The whitespace case sits in a test named `test_empty_email_is_rejected`, and the suite has 3 tests.
   - This suggests the existing empty-email test was rewritten rather than a new test added. If so, `""` and a missing `email` key are no longer tested directly. Their behaviour is still correct by reading.
   - Effect untested, grade nice-to-have. The settling check is the session's diff of `tests/test_validate.py`.
