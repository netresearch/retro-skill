### Finding 1: the new output breaks a documented procedure
This is a defect in the delivered change. The signal is B21, found but unreachable, with the B22 decision-point record attached.

**What the output used to feed:**
- `inputs/docs/operations/on-call.md` says on-call reads "the error printed for that host" for each failed host, then decides per error:
  - `disk full` or `health check timeout`: retry the host once.
  - any other error: run `rollback.sh <host>`.
- The same file says: "The rollout keeps no log file; the printed result is the only record."
- `inputs/docs/adr/0004-no-central-log.md` adds that `results.json` is overwritten by the next rollout.

**What is now missing:**
- `checks.json` shows the old output carried `web-02: FAILED: disk full on /var`, `web-05: FAILED: health check timeout after migration` and `web-09: FAILED: package signature rejected`.
- The new output only says `3 of 12 hosts failed`.
- With it, on-call cannot tell that web-02 and web-05 need a retry and web-09 needs a rollback.

**Decision point (turns 03–05):**
- *Warning sign:* the docstring the agent read stated the output contract: per-host errors.
- *Check it called for:* search for who consumes `report.py` output before changing that contract. A search for `report.py` in `docs/` finds `on-call.md`.
- *What the agent did instead:* rewrote the contract and checked only the exit code.

**What speaks against the finding:**
- The user asked for "shorter" and accepted the result.
- The user may be the only reader of this output.
- `results.json` still holds the errors until the next rollout.
- The case is not one of the five listed B22 warning signs. That is why it is reported as B21 with the B22 record attached.

**How it was reached:** I listed all 39 files under `inputs/` and searched them for report, `results.json`, log and on-call. `on-call.md` is the only consumer. `AGENTS.md`, `README.md`, `docs/architecture.md` and the `report.py` docstring do not point to it. `README.md` only says "Documentation is under `docs/`".

**Effect:** shown with the recorded run in `checks.json`. The fix below is untested, because no code could be run.

### Proposal 1 (repository, one PR): fix the output and add a test
- **Destination:** a code fix in the session's own work, plus `harness-artefact`.
- **Code fix:** shorten `report.py` by dropping the `ok` lines, not the errors. It prints one line per failed host with its error, then the summary line. The exit code stays as it is. The original docstring already describes this. The user's goal ("shorter when I check a rollout") is met: 13 lines become 4.
- **Test:** add `tests/test_report.py`. It runs `main()` on a fixture shaped like `results.json` and checks three things:
  - every failed host's name and error appear;
  - no `ok` host appears;
  - the exit code is 1.
  It also needs one case that must not fire: an all-ok fixture, which gives exit 0 and no host lines.
- **Expected calibration (not run):** the test should fail on `after/report.py`, because the errors are missing. It should also fail on `before/report.py`, because the `ok` lines are printed. It should pass on the proposed version.
- **Where it runs:** CI already runs `make test`, through `.github/workflows/ci.yml` and the `Makefile`. The repository has no hook config. Bootstrapping a hook framework is a separate decision, so this is tier 1 in CI only.

### Proposal 2: make the runbook reachable
- **Destination:** `canonical-source` (team record: repository docs), by PR.
- **What changes:** only links are added. No new page, because the runbook exists and is correct.
